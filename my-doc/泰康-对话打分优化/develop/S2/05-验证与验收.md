# S2 验证与验收

日期：2026-11-12。本页为实施后的验收计划；尚未执行 S2 模型任务，也没有 S2 性能结论。

## 1. 验收分层

| 层级 | 必须检查 | 处理方式 |
| --- | --- | --- |
| 来源与执行 | 输入未变、ID/版本合法、原文定位、回执覆盖、幂等与取消 | 不满足阻断当前单元，交付标记缺口 |
| 语义质量 | 维度边界、方法替代、局部反证、适用性 | 不确定可 deferred/needs_review，不反复要求 Seed 强行通过 |
| 评分可用性 | 档位能否判断、是否重复计分、业务事实依据 | 可 rubric_pending/evidence_only，不能宣称正式校准完成 |

允许零发现、单例、暂不归并、名称待改、候选档位待校准。宽松验收不允许来源造假、把普通问候硬变亮点、把明确反证标为纯正向支持。

## 2. 工程测试矩阵

测试进入 `tests/miner/skill_miner/` 按职责命名，fixture 放 `tests/support/`，不导入其他 test 文件，不依赖 `my-doc` 历史制品。

| 用例 | 可观察的预期结果 |
| --- | --- |
| 同一案例成功回执被重复投递 | 只产生一组 Evidence，不重复增加计数 |
| POST 超时但 OV 已受理 | 同一幂等键对账，不重复提交另一个 Compile |
| 一个批次中单个 child 失败 | 其他成功回执可用，只补偿失败单元 |
| 多批出现同一评价目标 | 后续关联既有维度，不反复生成完整评分口径 |
| 并行 match 同时未命中同一能力 | 材料进入同一待发现池，集中 register，不并发创建正式维度 |
| register 中 registry revision 改变 | CAS 拒绝旧决定，重做受影响比较，无覆盖写 |
| 初次召回漏掉同义维度 | 扩展匹配或新建前目录分页比较能发现目标；缺页不能判为全库无匹配 |
| A≈B、B≈C 但目标不同 | 不按传递闭包直接强并，保留边界/uncertain |
| 一个维度拥有大量成员 | 模型包大小受上限约束，成员映射在宿主，不累计附入正文 |
| 长句与单行 JSON | 检查真实字符/字节/Token 预算，不只按行数限制 |
| 预算不足 | 可拆单元有父子覆盖；不可拆完整案例进入 capacity_pending，无静默截断 |
| 模型返回外来成员或错误版本 | 当前单元被拒绝，不能让默认值修复成合法语义 |
| 模型遗漏部分 match/audit 成员 | 标记缺回执并补偿，不能按已读取计算完成 |
| 修改维度适用条件或新增维度 | 对全部案例补查该维度，原 N/A 也重新检查 |
| 仅修改显示名称 | 保留语义版本关系与合法统计，不无条件重跑所有案例 |
| novelty/revise 达到上限 | 停止新增循环，未解决项显式保留，已完成结果可交付 |
| 凭证、租户和权限边界 | 日志不含明文凭证，跨租户 ID/OV 路径拒绝 |
| Worker 租约过期、服务重启 | 过期写回被 fence 拒绝；从 PG 继续，不依赖本地残留 |
| 用户取消且远端终态未知 | 停止新单元，保留对账及远端占用信息 |
| Skill 配置在任务中途更新 | 已受理 job 始终使用原正文和阶段摘要 |

schema 校验器和阶段裁剪器优先进行确定性测试；不编写只检查某段文案字面出现的业务测试。

## 3. 默认 Skill 替换专项验收

这是 S2 的必验功能，不是可选上线操作。

1. 无覆盖配置时，settings 返回的新 default/effective 都等于生产 S2 资源。
2. 前端 textarea、查看默认、恢复默认、刷新后的值一致。
3. 当前目标泰康配置即使已保存旧正文，也在一次性迁移后直接使用 S2；无需手工复制或恢复默认。
4. 旧正文、原 revision、迁移后摘要有 PG 审计记录；并发保存引起的 CAS 冲突不会被覆盖。
5. 迁移再次执行不清除用户之后编辑的内容；其他租户自定义不被批量重置。
6. 创建任务后，job 的 execution_protocol、skill_body_snapshot、skill_hash 与页面有效值一致。
7. Worker 生成的阶段正文只包含 common、transport 和指定 stage，来自冻结正文；每个阶段 hash 可追溯。
8. 新协议不出现旧 single-candidate 警告，不要求产生团队 Skill Candidate。
9. v1 在途任务保留旧路由；新默认任务进入 v2，不能误入 plan_merge。
10. 文档包 Skill 与生产资源摘要一致；真实预检的 OV 有效计划符合一次文件 Map 加 Finalize。

## 4. 业务案例验收

用小规模人工标注的去标识化 fixture 验证判断方向，不要求所有自然语言输出完全一致。

| 场景 | 应有行为 |
| --- | --- |
| 只有“你好、谢谢” | 可以零发现；不强制创建关系建立评分项 |
| 教育和养老分别探询客户目标 | 比较同一评价目标，允许共享维度与不同情境方法 |
| 询问收入和询问保障额度 | 不能仅因都是询问就合并，应比较采集、核实或量化等评价目标 |
| 客户连续拒绝面谈，HWP 自行改时间 | 记录尝试与反证，不把频繁改时间等同尊重安排 |
| 客户纠正夸张赞美或目标假设 | 保留纠正的句子，检查后续是否承接，不自动判为共情成功 |
| 询问目标与现有储备后急促锁价 | 局部量化可支持，其他行为可以 mixed/counter，不重判整条案例优秀与否 |
| 客户追问应备/已备数字来源但未获解释 | 不宣称已经核对清楚；适用机会充分时记录局部问题 |
| 一种协商方法被另一种合理方法替代 | 不要求全部方法都出现，不重复计分 |
| 没有异议的简短约访片段 | 异议处理维度 N/A；不能机械零分 |
| 对话在客户提出问题处结束 | 根据片段不足判断 NE，不自动认定 HWP 忽略问题 |
| 客户模拟器输出系统式异常 | 该回复不作为满意度或信任证据，保留可用的其他片段 |
| HWP 宣称某权益写入合同但未提供合同 | 记录口头行为与 reference_required，不背书业务事实 |
| 维度仅有一个有效案例支持 | 允许候选或场景项；不冒充广泛验证 |
| 同一能力的多种同义名称 | 保留一个规范身份和方法差异；无法确认时待核实，不按标题硬删 |

真实业务复核以 Evidence、边界和可判定性为主，不能只看维度数量下降或 JSON 全部通过。上述问题可局部隔离，不要求整轮无限重跑。

## 5. 真实执行验证顺序

1. **协议预检**：读取部署中的 OV 能力，验证 Embedding、文件 Map、FileResponse、任务完成与内容读取；没有业务全量模型结论。
2. **小范围贯通**：从不同场景选择约 8 条原始对话，包含正向、mixed、短片段和模拟器异常；使用正式同一流程。
3. **重复归属检查**：选择约 20 条包含跨场景同能力和相似话术的对话，验证 register 复用、待发现池和回投。
4. **171 条完整运行**：在小范围接口与业务问题已收敛后执行；只有原始对话作为业务输入，不复用 S0 分析结果。

这些是开发测试批次，不是用户使用产品必须手动运行的多套流程。实际产品一次提交完整数据后自动完成所有阶段。

如果沿用旧 20 条测试集合，要记录其“4 个知识点各取最短 5 条”的偏差；不能据此声称覆盖全部 27 个知识点或整个保险销售领域。

## 6. 性能记录

每轮记录至少包括：

- 输入案例数、原话/模型视图字符数、提取 Evidence 数。
- stage 级模型单元数、Compile 次数、重试/修复/对账次数。
- register 复用数、新增数、不同阶段产生的 proposal 数。
- match 直接命中、扩展命中、routine、uncertain 与 unmatched 数。
- 模型 input/output/cached Token，明确是否覆盖 Entry/Planner/Review/压缩；缺失记 unavailable。
- preparing/queue/pipeline/committing/host_validation 的墙钟分解，无法拆分时不冒称纯模型耗时。
- 峰值业务包大小、实际请求上下文大小的可取得指标、429 次数和等待时间。
- audit 总计划对数、有效完成对数、修订后的失效及重查数量。
- 最终 rubric 单元数，成功消费次数应等于实际有评分口径回执的最终维度数。

性能目标为减少重复定义与评分生成，并控制固定开销。必须同时核对业务结果，不能通过少处理案例、少做适用性检查或删除反证宣称加速。

历史 S0 报告可作为背景；不同模型配置、服务负载或数据规模下不能直接计算加速比。如需正式比较，使用同一冻结原始输入和执行条件的独立基准实验，实验不是产品依赖，也不把旧产物喂给 S2。

## 7. 完成条件

- 单次受理的 job 可自动到最终交付，用户不需要新建第二个提取/归并任务。
- 每个合法案例有提取回执或明确 pending/failed，不能静默消失。
- 每个 Evidence 有关联、普通、待核实等明确去向；语义多重关联不重复计案例数。
- 评分候选维度的 case × dimension 覆盖闭合；更改语义后的旧 audit 不参与当前统计。
- 最终每个评分维度有 rubric 或明确 pending；方法实例不自动变成计分项。
- 所有统计可由持久化记录重算，原文来源和版本可追溯。
- 网页默认替换与目标有效配置迁移通过专项验收。
- 报告区分 complete/partial、结构通过、业务待复核、尚未独立校准，不夸大结论。

遵守根 AGENTS.md 与 tests/README.md；根据最终代码变更运行必要检查：

```bash

.venv/bin/python -m pytest
npm --prefix web-ui test
npm --prefix web-ui run build
node docs/scripts/check-docs-refs.mjs --strict
.venv/bin/python -m pytest tests/contracts/test_docs.py
```
