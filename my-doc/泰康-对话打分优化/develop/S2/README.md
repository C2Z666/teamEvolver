# S2：优秀对话评分维度挖掘开发入口

日期：2026-11-12。状态：开发设计与配套 Skill 已编写，业务代码、配置迁移与真实模型验证尚未实施。

S2 从原始优秀对话开始，在一个任务内完成行为 Evidence 提取、共享维度库匹配、集中新增、全量原文检查和候选评分标准生成。原 S0 提取与归并产物不作为 S2 输入，不要求用户运行两套流程。

## 必须落实的用户要求

1. 一次启动、一个 job、自动衔接全部阶段，最终交付一套评分标准及来源材料。
2. 从原始对话重新提取；不导入旧 findings、旧 dimensions、旧评分口径。可以使用已有准备数据中的原始白名单对话与来源索引。
3. 每条案例的成功提取只执行一次；失败单元可以有限重试，后续检查不是第二轮开放式提取。
4. 优先匹配共享维度，未匹配材料集中新增；各案例组不得分别创建一套正式维度后再全量归并。
5. 不重新判定整条案例是否优秀；允许局部普通行为、反证、零发现与暂不确定。
6. 适配 Seed 与 OV 的容量限制，不使用全量大 Reduce，不依赖长历史压缩完成分析。
7. **实施时直接将网页 Skill 挖掘配置的默认 Skill 替换为本目录的新 Skill。初始值、查看默认、恢复默认、新任务冻结正文必须一致。目标泰康配置中的旧有效正文也要迁移，不能要求用户自行复制粘贴或手工点恢复默认。**
8. 上述替换属于 S2 开发和部署要求；本次文档交付不代表运行配置已经改变。

## 固定的首版技术路径

S2 使用 teamEvolver 编排业务状态机，PostgreSQL 保存可变状态，现有 OV Compile 执行有界的单阶段文件 Map，OV 提供 Embedding 与知识制品能力。每次 Compile 只采用一次 Map 和一次 Finalize。Seed 继续使用 OV 服务端配置。

宿主直接通过 `teamEvolver/llm.py` 执行模型阶段可作为后续优化，**不属于 S2 首版双执行器要求**，不在网页增加两套运行模式。

全流程可概括为：

```text
prepare → extract → bootstrap → match → novelty → audit → revise → recheck → rubric → assemble
```

其中 bootstrap/novelty 调用相同的 propose 与 register 阶段；没有两个独立挖掘任务。空阶段自动跳过，修订次数有界。所有参数在受理时冻结。
