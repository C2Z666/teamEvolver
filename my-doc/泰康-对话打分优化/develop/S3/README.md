## 已确定的要求

1. 稳定执行完优先。继续强制进入一次文件 Map + Finalize；不采用 Entry 直接生成结果，不由 TE 直接调用模型代替 OV。
2. 完整阅读分配内容，在同一次提取中选择有方法信息的行为；不先全量提动作再启动第二轮筛选。
3. “全部案例整体优秀”是来源前提，不代表所有寒暄都要独立提取。保留局部、少见但具体的做法，不用频率、客户配合或已有维度作为提取门槛。
4. 每个 Map 子任务初版仍只处理一个案例；长案例按预算做有来源定位的有界分段。扩批优先增加一次 Compile 调度的独立任务数，不增加单次模型处理的案例数。
5. 同一案例的紧密关联动作可以构成一条 Evidence；不同案例中的相似行为保留各自来源，不进行跨案例语义去重。
6. OV 项目不修改。不承诺靠 Skill 实现跨 Compile 计划缓存、跳过内部 Review 或关闭 Compile 输出知识加工。
7. 一个 job 自动完成准备、提取、校验和导出；成功单元不重复提取，仅失败单元有限修复或拆分。局部失败明确 partial，不能无限重试，也不能冒充完整成功。
8. **后续实现必须把本目录 Skill 写入代码中的默认编译 Skill，并切换网页默认、查看默认、恢复默认及新任务快照。目标泰康已保存旧正文也需一次性迁移；只增加可选模板不算完成。**

## 协议与实现边界

- 新执行协议：`te-dialogue-evidence.v1`。S3 是开发阶段编号，协议从 Evidence 专用 v1 开始，不冒用 S2 协议。
- 新 Skill 名：`taikang-dialogue-evidence-s3`。
- 原始案例继续支持 `taikang.dialogue-case.v1`，不读取 S0/S2 的分析结果作为新任务输入。
- 本目录 Skill 供 OV Compile 使用，不是安装到 Codex 的个人 Skill；不包含 Codex UI 元数据，也不依赖本目录开发文档作为运行附件。
- 本次只新增设计文档与 Skill；生产代码资源、默认配置与部署切换属于后续实现。

```text
受理与冻结 → prepare → plan_units → extract → assemble → delivery
                                 ↑           |
                                 └─有限拆分/修复─┘
```

`plan_units` 是 TE 的确定性打包，不调用模型。`extract` 是唯一业务模型阶段；OV 内部仍可能有 Entry、Planner、Map、Review 等调用，不能把“一个业务阶段”宣传成“一次模型调用”。
