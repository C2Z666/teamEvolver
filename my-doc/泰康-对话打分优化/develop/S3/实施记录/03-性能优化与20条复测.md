# S3 性能优化与 20 条复测

日期：2026-11-16（北京时间）。本轮完成宿主侧优化并启动 20 条真实测试；实际性能与质量改善需等待本轮终态后与首测比较。

## 已实现

- 新受理任务冻结 adaptive_policy_version=2，从 2 单元起步、最多 4 单元，保持一个在途 Compile，输入字符/字节预算不扩大。
- 同一批量连续 3 批正常完成，实际 token 与耗时均不超过软预算的 75%，才增加一个单元试运行；不再把单条包含固定成本的总耗时乘以目标单元数。
- 字段隔离、普通回执错误不触发全局缩批。限流、容量信号、超时、超过实际 token/耗时软预算仍立即减半，最低一个单元。缺失消耗不扩批。记录每次资源压力和扩批阻断原因。
- 普通提取优先，字段修复独立组批。针对 scenario、trigger、response_refs，只发送受影响 Evidence、冻结原文与具体错误，模型返回字段补丁；宿主限制可修改的字段集合、验证身份与原回执摘要，合并后重新执行完整回执校验。未支持的隔离仍保留原有有界回执修复。
- 无效补丁立即保留原先可用回执，避免为修复单个字段反复重提取。原回执、补丁与合并结果的摘要和 URI 保留血缘；合并产物写入独立 OV 路径，PG 保存验收状态。写入回执响应丢失后可重启恢复。
- 字段补丁使用冻结 Skill 的独立 repair 分段与独立执行摘要；历史任务不自动切换策略或修复模式。原有提取 Skill 分段仍可读取。
- 运行指标增加输入准备、提交、受理、观测远端阶段、远端终态与回执完成时间；展示扩批阻断原因、正常提取/定点修复类型。导出包含实际修复 Skill、补丁 Schema 和 field_repairs.jsonl 血缘。

本轮没有修改 OpenViking 的 Planner、Review、目录索引或版本提交实现；新增观测仅记录宿主能看到的阶段，不能据此精确拆分 OV 尚未公开的内部耗时。
